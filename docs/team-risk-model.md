# 组内前端风险模型

## 静态高置信规则

- 路由转换：已有component的路由被克隆进children后，必须验证最终path、name、component。
- 表格选择：启用rowSelection必须提供稳定rowKey，且响应数据必须包含该字段。
- 表单Schema：field不能为空，也不能重复；纯展示字段同样要有唯一key。
- 弹窗提交：请求必须await，成功后按“刷新列表 → 关闭弹窗”或团队约定顺序执行。
- 消息提示：框架层和业务层只能有一层负责成功/失败提示。
- 接口类型：禁止用Object作为业务接口参数类型。

## 需要运行态场景确认

- 路由空白页：用真实菜单逐级进入，记录最终路由和页面根节点。
- 全选/筛选：选中记录、执行筛选、取消筛选，验证selectedRowKeys仍对应当前数据。
- 弹窗样式：打开新增、编辑、删除确认弹窗，检查宽高、footer和按钮区域。
- 列表刷新：提交成功后等待接口完成，断言列表接口重新请求且新数据出现。
- `_dictText`回显：检查详情响应中每个字典值都带文本，或能由内部字典解析。
- 参数类型：记录请求payload，与维护的接口契约逐字段比较。

## AI改动守门规则

- Jeecg项目业务页面优先使用框架已有组件，包括BasicTable、BasicForm、BasicModal、JUpload、JDictSelectTag和已有公共业务组件。
- 只有框架组件不能满足需求、第三方能力必须直连或正在编写公共组件封装时，才允许直接使用底层Ant Design Vue组件。
- 特殊情况必须说明原因，可在文件中添加`audit-allow-jeecg-component: <组件名> <原因>`；禁止无原因豁免。
- 不允许新增未在内部字典中登记的options。
- 不允许为接口必填/可选字段擅自补空串、0、固定ID或默认状态。
- 不允许在已有框架提示的接口后再次添加message。
- 发现契约不明确时生成“待确认项”，不能自行假设业务值。

## 请求触发策略

- 所有用户可感知请求必须有局部loading；提交按钮在请求结束前保持禁用。
- 搜索输入使用防抖，默认300ms；连续滚动、resize等高频事件使用节流。
- 新增、修改、删除不使用普通防抖代替并发控制，应使用提交锁、幂等键或请求去重。
- 列表初始化和明确的手动刷新不做防抖，避免旧响应覆盖新状态时应取消前序请求。

## 操作按钮与弹窗

- 查看、编辑、通过、驳回、删除、取消使用固定且不同的语义颜色，配置见`config/ui-policy.json`。
- 二次确认弹窗按按钮数量设置最小宽度：1个320px、2个400px、3个520px、4个及以上640px。
- footer必须允许合理换行，按钮不能越界、重叠或被裁切。

## ECharts数据更新契约

- 图表实例只初始化一次；更新数据调用已有实例的`setOption`。
- 接口数据和图表配置必须分离，响应式数据变化要有明确的`watch/watchEffect`或统一刷新调度。
- `resize`只负责容器尺寸变化，不能替代数据`setOption`。
- 刷新前后的接口版本或数据摘要应变化，图表实例的series数据也必须随之变化。
- 重复初始化前必须`dispose`，事件监听和轮播定时器必须先清理再创建。

## 单点登录与待办回跳契约

- `ticketUac=-1`是进入统一认证前的占位状态，必须先调用`getCheckLoginUrl`，再由浏览器跳转到可信认证地址。
- 只有收到非`-1`的真实票据后才能调用`validateLogin`，禁止把占位票据提交给校验接口。
- 登录态、用户信息和动态路由初始化完成后才能处理`redirect`，避免目标页面因权限尚未就绪而白屏。
- `redirect`只允许站内相对路径或同源地址，并应在往返认证地址时正确编码和保留。
- `redirect`为空时的默认目标必须由产品契约明确，不能由编码Agent自行猜测。
